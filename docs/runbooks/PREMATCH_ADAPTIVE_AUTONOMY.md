# PREMATCH adaptive learning and production health

This release is opt-in. Merely importing it, checking status, or installing a checkout does not activate a model or start a timer. LIVE remains paused: no LIVE worker, timer, bootstrap, training or publication is part of this procedure. Official policy, ledger, bankroll and destinations are outside this integration.

## Accepted baseline and inference

`EXISTING_PREMATCH_BASELINE_V1` is a reviewed adapter around the accepted `0c4f316248e55f504b780cdef4e25165b800a779` signal/profile inference. It has no invented coefficients and is not fitted to the current small forward sample. Its immutable descriptor includes accepted commit, policy identities, stream, contract and fingerprint. Each future opportunity freezes the raw signals, profile, missing inputs, contradiction flag, exact market and odds before inference. Returning original signals for this baseline preserves independent-family counts, lanes, probability, EV and readiness.

The synthetic golden fixture was generated by importing the accepted production checkout. It covers 13 profiles × 11 markets with exact Decimal equality. This proves the inference adapter at the frozen signal boundary. It does not claim unchanged upstream data processing: the release deliberately fixes regulation-score parsing, conflicting history rows, league isolation, cache budgeting, persisted-context expiry/identity checks and one classification entry. Real historical signal replays cannot recreate unfrozen upstream history or lineups.

## Automatic path after deployment

* Discovery runs the registered PREMATCH champion inside the existing market/value/freshness/publication shell. An optional challenger consumes those same pre-outcome opportunities. It has no Telegram transport and cannot publish. Discovery records compact cycle health, including failures, quota reduction, coverage, lanes and blockers.
* Existing single/combo settlement persists its authoritative immutable results. PREMATCH observation linkage and governance run after settlement without training. The same bounded settlement worker can resolve otherwise-unpublished shadow fixtures, with a maximum overall 21 request attempts including status/retries. No second discovery scan is added.
* The observer runs every 30 minutes, reads the source ledger with SQLite `mode=ro` and `query_only=ON`, imports unique safely linked observations, settles shadow labels from persisted final results, evaluates promotion/rollback and stores metrics. It has no provider or Telegram transport and does not train.
* The daily 04:15 job checks stage, at least 50 new binary settlements and seven days since the previous research cycle. It trains outside the adaptive database write lock; an immutable batch commits only if champion/research state has not advanced concurrently. A current challenger blocks competing research.
* Zero through 99 resolved observations: `LEARNING_AND_OBSERVING`. At 100: `EARLY_RESEARCH`, bounded offline validation only, no holdout consumption or promotion. At 200: `CHALLENGER_RESEARCH`; holdout requirements still apply. At 500 resolved observations spanning 90 days: `FULL_AUTO_LEARNING_ELIGIBLE`; this alone never activates a model.
* Candidate families remain LOGISTIC, REGULARIZED_LOGISTIC, STUMP_ENSEMBLE and CALIBRATED_ENSEMBLE. Search varies safe features, interactions, regularization, history windows, time decay, calibration and eligible specialists; maximum 50 specs, bounded rows/iterations/operations. Missing features retain missing indicators. Rich context names in the schema do not imply those inputs exist in production. No generated Python or opaque framework was added.
* Datasets are immutable chronological TRAIN/VALIDATION/SEALED_HOLDOUT with fixture grouping, result-availability checks and a 24-hour embargo. Validation chooses at most one holdout candidate. Consumed holdouts are recorded and excluded from repeated testing. A 20% holdout with minimum 100 fresh observations means a 200-row research cycle will normally not produce a challenger.
* Promotion requires global 500/90-day eligibility, sufficient fresh holdout, reproduction, probability validity, Brier/log-loss/calibration, risk, subgroup/stability, throughput and confidence gates, then at least 100 resolved matched shadow opportunities over 30 days. Only PREMATCH's Lab pointer changes, atomically. Previous artifacts remain immutable. Baseline rollback needs the frozen baseline context; legacy observations lacking it are never fabricated.
* Integrity failures may roll back immediately to a verified predecessor. Performance rollback requires at least 200 observations and 30 days plus severe degradation gates. A few losses are insufficient. An invalid initial champion without a valid predecessor fails closed.

The synthetic scheduler-style test runs observation, early research, challenger research, holdout, future shadow observations, automatic settlement/promotion, corruption detection and rollback. These are disposable data and artifacts, not real model evidence. A successful test does not predict profitability.

## Data and statistical isolation

Schema version 4 includes append-only `cycle_health`, `observer_runs`, and weekly reports/claims/receipts/unknown-delivery records. Existing source records remain authoritative. Dedicated adaptive DB only; foreign keys and append-only guards remain required. Product statistics include every published loss, including legacy records without complete learning provenance. Valid observations are separately linked and deduplicated across single/combo legs. Combo outcomes never enter binary calibration. LIVE data never count toward PREMATCH gates.

All reports retain W/L/V, actual captured odds, flat-unit PnL/ROI, Brier/log loss, calibration bins/ECE/bias, drawdown, streaks, Wilson context and bounded segment summaries. Associations are not causal explanations. There is no Martingale, stake change, bankroll-dependent probability, loss-triggered threshold relaxation, forced bet count or relaxed odds freshness.

## Quota integration

Discovery and settlement must receive the same `--adaptive-database` path. Every HTTP attempt, including status preflight and retries, is reserved before dispatch and reconciled against real response headers. Claims survive restarts. PREMATCH's existing 1,500 safety reserve plus settlement headroom is not lowered. LIVE reserves exist in the common manager but no LIVE worker is enabled. Observer and research normally consume zero calls. Legacy workers without the common database are not magically covered; do not claim cross-process protection until both service commands are updated. Provider headers also reflect callers outside these workers.

The September 18 audit observed successful timer execution but quota-reduced discovery coverage, with insufficient independent evidence in evaluated markets. Reusing still-valid cached histories/predictions must not require network headroom. Near-kickoff required refresh still cannot use those caches. Healthy silence means complete-enough evaluation with explicit blockers; quota-starved silence remains DEGRADED.
